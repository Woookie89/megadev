# P59 · A summary number is a claim: recompute it from raw events and check whether the action moved off the measured path

> Chapter [2. Contracts and "done"](README.md) · episodes: S03E05

> **Lessons:**
>
> - S03E05 · Products That Learn After Release → chapter "Observation" — [original (EN)](../../s03e05-products-that-learn-after-release.md#observation) · [Polish: „Obserwacja”](../../pl/s03e05-products-that-learn-after-release.md#obserwacja)
> - S03E05 · Products That Learn After Release → chapter "Synthesis" — [original (EN)](../../s03e05-products-that-learn-after-release.md#synthesis) · [Polish: „Synteza”](../../pl/s03e05-products-that-learn-after-release.md#synteza)

**Principle.** A summary generated by a tool or an agent ("clear win, expand") is a claim, not
a signal. Before you give a verdict: recompute the metric and every guardrail from the raw
events, watch what people actually do (recordings, calls), and ask which path the metric
counts. If the action could have moved off that path, the win is not proven. A recomputation
that agrees does not end the work.

**Why.** A metric counts only what somebody logged. When people change route (another tab,
another tool, a manual step, an event that replaces another one), the counter drops without
anything improving. Matching arithmetic gives false confidence, and a model readily confirms a
number it managed to reproduce. The lesson lists intended against actual results, workarounds
and unintended effects among the things to observe. It also says signals must be read together
with other signals, not one at a time. A number without behavior is one signal.

**Case.** S03E05: `summary.md` said about release 0008 (smart suggestions v2): "clear win,
expand". The harness recomputed from `events.csv` (16,813 rows): restarts per bad night 2.751
in control and 2.422 with the flag (−12%), in both weeks and every night, and no site in both
arms. The numbers were right. But `call-02` said: "After we accept we go back to the other
screen, same as before, everybody on nights does", and `replay-02` and `replay-04` showed that
after Accept the queue stays stuck and the operator restarts `booking-worker-2` in the
`sched-admin` tab, which the board does not log. In `events.csv`, incidents `inc-24201` and
`inc-26406` have an accept and a resolve, but no restart event. Verdict: `investigate`, an
owner decision (the release stays at 50%, restarts from `sched-admin` start being logged, and
the result is measured again for 14 nights).

In the second batch the same method gave the opposite result. Release 0010 (auto-close) cut
open incidents at 06:00Z from 341 to 267 (−21.7%, target 20%). The TTR guardrail, counting
auto-close as the end, came to 24.28 min in control and 26.28 min with the flag (+8.2%, limit
+5%). Counted over `resolved` only, it would have been 22.7 min, because 199 auto-closed
incidents have no `resolved` event. `replay-05` and `replay-06`: an incident closed with a
queue of 1,446 (`replay-05`), and in `sched-desk` the tickets `tk-6e41b2` and `tk-a93c58` still
open. "Closed" did not mean "resolved". Verdict: `revert`. Release 0011 (bulk acknowledge)
passed the same test: open→ack −39.5%, missed pages +0.34 pp, ack→resolved +4.7%, and the
queues in the recordings fell to 0. Verdict: `expand`. CI gate `ci-1222` had "diff: none", so
it tested nothing, while `ci-1247` (+226 −48) and `ci-1250` (+174 −36) tested real changes. The
rule the harness kept in its claim: "A metric that counts only one logging path (board
restarts) cannot prove a win; check whether the action moved off the measured path before you
expand." It wrote the rule itself; the course did not supply it.

**Apply.**

- Recompute the metric and every guardrail with a script, per arm. Check that the arms are
  separate (no site in both) and state the size of each.
- For a "less of X" metric, ask where X could have gone: another tab, another tool, closing
  without resolving.
- Count the guardrail twice: as the record defines it, and honestly. If one event replaces
  another (auto-close instead of `resolved`), do not drop those cases from the median. Give
  both results and the margin ("+4.7% against a limit of 5%"), not just "passed".
- Watch at least one recording per arm and per release. Listen to every call. "Everybody does
  it" is a signal.
- Check the diff size of every CI gate. "diff: none" is a gate that tested nothing
  ([P58](p58-the-checker-is-a-spec.md)).
- When the recomputation and the behavior agree, say so plainly and apply the recorded
  decision (0011). Distrusting a summary does not mean refusing it.
- A result the data cannot settle that concerns product direction is an owner's decision
  ([P51](../07-human-in-the-loop/p51-a-written-rule-sets-the-autonomy-line.md)). Write the rule
  from such a round where a session will load it
  ([P16](../03-memory/p16-durability-ladder.md)).
